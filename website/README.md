# Website source of truth

## Production architecture
The public website is built with Astro from `website/`. GitHub Pages is the canonical production host. The workflow `.github/workflows/publish-github-pages.yml` runs `scripts/build-website.sh` and publishes the assembled `dist/` output.

The root `index.html` is a legacy file and is not the deployed homepage source. Changes to the public homepage belong in `website/src/pages/index.astro` and its components/layout/styles.

## Main source locations
- Homepage and navigation: `website/src/pages/index.astro`
- Shared page layout and Supabase bootstrap: `website/src/layouts/SiteLayout.astro`
- Global styles: `website/src/styles/global.css`
- Public catalogue: `website/src/components/PublicCatalogue.tsx`
- Public booking and feedback: `website/src/components/PublicBookingForm.tsx`, `PublicFeedbackForm.tsx`
- Member account markup: `account/index.html`
- Shared account/auth/Founder Studio behavior: `assets/app.js`
- Shared browser styles: `assets/`
- Build assembly: `scripts/build-website.sh`

## Commands
Requirements are declared in `website/package.json` (Node.js >=22.23.4 and npm >=9.6.5).

```bash
npm --prefix website install
npm --prefix website run check
npm --prefix website run build
bash scripts/build-website.sh
```

The full assembly script copies the Astro build and shared routes, normalizes the booking-confirmation audio asset, generates sitemap data and checks required output. Use it for final production-output validation; `astro build` alone does not validate the assembled account/admin site.

## Content and SEO
Service pages live under `website/src/pages/services/`; editorial pages live under `website/src/pages/journal/`. Public artist/release routes and sitemap entries are generated by the scripts under `scripts/`. Inspect those scripts and the corresponding Astro route files before changing visibility filters or claiming that draft content is indexed.

Canonical URLs and social metadata are configured in `website/src/layouts/SiteLayout.astro`. Keep the root `robots.txt` and `sitemap.xml` aligned with the actual GitHub Pages base URL and generated pages.

## Backend and access
The website uses the existing Supabase project. Only the project URL and publishable key may be included in browser output. RLS and server-side checks must enforce member and Founder access. Do not move secrets into `assets/` or expose private media to fix a UI issue.

## Deployment and verification
- GitHub Pages is the production host; do not configure Netlify as the canonical deployment.
- Feature branches and previews are not production publication.
- Verify the Pages workflow and live URL after a merge to `main`.
- Test the public catalogue, authentication redirects, account page, Founder Studio authorization, booking/contact forms, media playback and downloads in the target browsers.
- Report the exact checks performed. A successful Astro build does not prove Supabase, OAuth, uploads or playback work in production.
